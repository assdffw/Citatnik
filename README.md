# Витрина цитатника

Один процесс на asyncio (aiohttp), всё состояние в памяти. Порт 8000.

## Запуск
    docker build -t vitrina .
    docker run --rm -p 8000:8000 --memory=256m --memory-swap=256m --cpus=0.5 vitrina

Без Docker: `pip install -r requirements.txt && python main.py`.
Самопроверка: `python selftest.py` (см. шапку файла).

## Как устроено
**Хранение.** `known` — множество id всех цитат каталога (ими считаются `catalog` и `dropped`).
`local` — LRU-кэш готовых JSON-байтов с бюджетом ~44 МБ (укладываемся в 256 МБ; пик при приёме
полного снимка ~150 МБ у процесса). Записи отдаются как готовые байты, без повторной сериализации.

**Свежесть (обещано 60 с).** Запись отдаётся локально, только если ей не больше 50 с
(возраст считается с начала приёма снимка либо с момента запроса к каталогу). Если запись
читают и ей больше 35 с, она обновляется из каталога в фоне — читатель не ждёт, а запись
не успевает устареть.

**Бережём каталог.**
- singleflight: одновременные запросы одной цитаты — одно обращение в каталог;
- не больше 6 обращений одновременно, не больше 16 фоновых обновлений;
- 503 + `Retry-After`: общая пауза на указанное время, читатели получают быстрый 503 с `Retry-After`;
- каталог не отвечает: после 3 неудач подряд обращения прекращаются, остаётся один пробный запрос
  с растущей паузой (1, 2, 4 … 15 с). Читатели получают 503 мгновенно, `/health` и локальные ответы
  не страдают;
- читатель ждёт не дольше 2,5 с, обращение к каталогу обрывается через 2,2 с.

**Снимок.** Тело разбирается построчно потоком, между чанками управление отдаётся циклу событий.
Некорректные записи пропускаются (в `imported` не входят). Плохой заголовок, обрезанный снимок
или данные после `]}` — 400, состояние `known` не меняется. Записи, ушедшие из снимка, удаляются из
локального хранилища и в `evictions` не считаются. Снятия (DELETE) действуют до следующего снимка.

**Допущения.**
- PUT/DELETE действуют только на витрине (в контракте каталога есть лишь `GET /quote/{id}`);
  PUT возвращает 200 и `{id, author, text}`; не-JSON/не-объект — 400, нарушение границ — 422.
- `served_from_catalog` считает только успешные ответы с `X-Source: CATALOG`.
- Если каталог недоступен, а локальная запись старше 50 с, читатель получает 503, а не устаревшие
  данные (`SERVE_STALE=1` включает отдачу устаревшего).
- Все пороги настраиваются переменными окружения (см. начало `main.py`).
